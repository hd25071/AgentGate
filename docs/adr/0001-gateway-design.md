# ADR-0001：为什么是"执行网关"，而不是"提示词防护"

- 状态：已采纳
- 日期：2026-09（P0/P1）

## 背景

给运维 Agent 接生产系统的常见做法是两层：给模型写"安全提示词"，
再在工具层加几段关键词黑名单（"如果命令里出现 FLUSHALL 就拒绝"）。

这条路有一个结构性问题：它把**是否安全**的判断交给了两样都不适合做判断的东西——
模型的自律性，和一份永远写不完的字符串黑名单。
Prompt injection 的研究现状是明确的：**没有可靠的注入检测**。
任何基于"识别恶意输入"的防线，都在一个攻方成本极低、守方成本极高的赛道上。

## 决策

把问题从"识别恶意输入"改成"约束可能产生的后果"。

Agent 完全不被信任，包括它的输入、它的推理、它的输出。
网关不判断一段文本是不是恶意指令，只回答一个问题：

> 这个已被结构化描述的动作，本身允许执行吗？

由此推导出全部设计：

1. **Action 是唯一的一等公民**。工具调用的原始参数必须被归一化成结构化 Action，
   后续所有环节只操作 Action，不再看原文（见 ADR-0003）。
2. **策略针对语义特征**，不针对字符串。因此变形攻击对策略无效。
3. **三方判定**（allow / approval_required / deny），默认 deny。
   二值判定会把所有边界情况推向"拒绝"，逼运维关掉网关。
4. **凭证不下发**。Agent 只持有短时效、带 scope 的令牌（见 ADR-0004 的背景）。
5. **审批绑定到动作哈希**，而不是绑定到"一次操作"（见 ADR-0004）。
6. **执行前必预演、可取快照、失败自动回滚**。
7. **每一次判定和执行都进哈希链审计**（见 ADR-0005）。

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 只用系统提示词约束 | 注入的定义就是"绕过提示词"。把它当唯一防线等于没有防线 |
| 在网关里做注入检测（分类器/正则） | 攻守成本不对称；误报会摧毁可用性；且无法覆盖未知注入 |
| 给 Agent 一个只读凭证 | 无法表达"这次删除需要人批"，也做不到参数级策略 |
| 所有危险操作一律拒绝 | 运维会直接绕开网关，最终安全等级更低（见 T8） |
| 用 K8s 的 RBAC / Redis ACL 做全部管控 | 它们没有"挂起等人批"这个状态，也没有跨系统的统一审计 |
| 做成 sidecar 代理 | 代理需要重新推导身份与语义；网关自己讲 MCP，能把"调用者身份"和"动作"绑在同一个对象上 |

## 后果

**正向**
- 变形/编码/夹带攻击在结构上无法绕过策略
- 误报可控（中风险是"找人批"而非"拒绝"），给了运维不绕过它的理由
- 每次拒绝都能给出具体原因和动作哈希，Agent 不会陷入"换种写法重试"的循环

**代价**
- 归一化器成为新的关键路径：**每个目标系统都要一份**，且必须覆盖该系统的全部危险语义。
  这是这个设计里最需要持续投入的地方
- 需要为"无法解析的请求"定义行为：本实现选择 fail-closed（拒绝）
- 引入了审批这个人工环节，必然带来摩擦
